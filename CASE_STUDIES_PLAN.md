# Case studies: editorial plan

Audience: practical builders who want concrete examples before evidence details.

Recommended direction: a linked three-case series. A long homepage would compete with the existing starting routes; terse cards alone would omit the decisions and limits. Keep a compact Work delivered overview and give each case an example, problem, repair, checks, evidence and limits, with back/home/next navigation.

1. Local validation: an author-reported repair account, separated from a fresh, runnable synthetic illustration of unchanged-file coverage.
2. Bazel BEP: compare the pinned public complete and truncated synthetic records. Explain what the adapter can and cannot establish.
3. Inspect AI: follow public issue, implementation, review, Trio repair and merge evidence.

Keep the approved visual style, artwork, hero and existing starting routes. Plain HTML/CSS; no dependencies, scripts in the browser or build step. Preserve independent project directions. Keep deployment manual and site-only. Validate links, fragments, source claims, synthetic output and rendered desktop/mobile/keyboard navigation before independent review.
